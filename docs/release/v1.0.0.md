# Dvx3 Backup Manager - Release v1.0.0 Notes

## SHA-256 Integrity Verification Feature

### What's New

The `v1.0.0` release introduces **SHA-256 integrity verification** for encrypted archives. This feature:

1. **Computes a SHA-256 hash** of the encrypted plaintext during backup creation
2. **Stores the hash** in the archive header (JSON field: `"sha256"`)
3. **Verifies integrity on restore** by comparing stored vs computed hashes
4. **Maintains full backward compatibility** - existing archives work without modification

### Usage

#### Backup with Integrity Verification (Default)
```bash
dvx3 backup encrypt ~/documents -p mypassword
```
This automatically enables SHA-256 verification for new backups.

#### Backup Without Integrity Verification (Legacy Mode)
```bash
dvx3 backup encrypt ~/documents -p mypassword --skip-integrity
```
Use this flag to create archives without integrity verification (e.g., for maximum compatibility).

#### Restore with Integrity Verification (Default)
```bash
dvx3 backup decrypt archive.dvx3 -p mypassword -o /restore/path
```
This automatically verifies integrity on restore for archives containing a SHA-256 hash.

#### Restore Without Integrity Verification (Legacy Mode)
```bash
dvx3 backup decrypt archive.dvx3 -p mypassword -o /restore/path --skip-integrity
```
Use this flag to skip integrity verification (faster, but less secure).

### How It Works

1. **During Encryption**: After compressing and encrypting your files, Dvx3 computes the SHA-256 hash of all plaintext content and stores it in the archive header.

2. **During Decryption**: Before extracting files, Dvx3 decrypts the archive in memory and computes a new SHA-256 hash. It compares this with the stored hash:
   - **Match**: Archive integrity verified ✅
   - **Mismatch**: Integrity verification failed ❌ (archive may be corrupted or tampered with)

3. **Error Handling**: If integrity verification fails, Dvx3 throws an `IOError.FAILED()` exception and does NOT write any files to the destination directory.

### Security Considerations

- **Detection**: Integrity verification detects ANY corruption or modification of archive content, not just common errors
- **Performance**: Requires full encryption/decryption cycle (acceptable trade-off for data integrity)
- **Memory Usage**: Currently accumulates all plaintext in memory during decryption (documented limitation)

### Technical Implementation

The implementation uses:
- **Algorithm**: SHA-256 (RFC 6234)
- **Storage**: 64-character hexadecimal string in JSON header field `"sha256"`
- **Verification mode**: Optional flag controlled by `EncryptionMode.WITH_INTEGRITY` enum
- **Default behavior**: Integrity verification enabled for new archives

### Backward Compatibility

All existing `.dvx3` archives continue to work:
- Archives without `"sha256"` field are automatically skipped
- No migration required
- Existing restore operations unaffected

## Troubleshooting

### "Integrity verification failed" Error

This error appears when the SHA-256 hash doesn't match. Causes include:
- **Archive corruption** from incomplete download or storage failure
- **Tampering** - someone modified the archive content
- **Wrong password** - decryption produces garbage data

**Solution**: Skip integrity check if you trust the archive source:
```bash
dvx3 backup decrypt archive.dvx3 -p mypassword -o /restore --skip-integrity
```

### "ValueError: [Errno 2] No such file or directory"

The CLI binary is missing from your PATH. **Solution**: Add it to your PATH or run directly:
```bash
./Dvx3-Backup-Manager-linux-x86_64/dvx3_backup_manager encrypt ./source -p password
```

## Known Limitations

1. **Memory Usage**: Current implementation accumulates all plaintext in memory during decryption for integrity verification. For very large archives (>10GB), consider:
   - Disabling integrity verification if you trust your storage media
   - Upgrading to a future version with streaming hash computation

2. **Performance**: Integrity verification requires full encryption/decryption cycle, which may be slower than skipping verification.

3. **macOS Build**: The macOS build requires fixing the gio-unix import issue before release. This is a minor fix and does not affect functionality.
