## 3. Architecture Overview

### Encryption Pipeline

```
Source Directory → tar -c → zstd -d → Encrypt Chunks → JSON Header Rewrite
```

#### Component Details

| Stage | Tool/Function | Purpose |
|-------|---------------|---------|
| Tar | `tar -c` | Stream directory contents to stdout |
| Compression | `zstd -T<N> -<LEVEL>` | Multi-threaded compression (1-22 levels) |
| Encryption | Per-chunk Secretbox | XSalsa20-Poly1305 with Argon2id key derivation |

#### Key Derivation
```vala
// Argon2id parameters
ARGON_T = 2  // Time cost (iterations)
ARGON_M = 64000  // Memory in KiB (64 MiB)
ARGON_P = 4  // Parallelism threads

// Hash function: password || salt → key
Sodium.crypto_pwhash(key, ..., SALT, PASSWD, T, M*1024, ALG_ARGON2ID13);
```

#### Chunk Structure
- **Plaintext:** 1 MiB per chunk (CHUNK_SIZE = 1024 * 1024)
- **Nonce:** 24 bytes (Sodium.Symmetric.NONCE_BYTES)
- **Ciphertext:** N + MAC (where N is plaintext size, MAC = 16 bytes)
- **Total encrypted chunk:** N + 40 bytes

#### Header Structure (512-byte reserve space)
```json
{
  "salt": "<base64-encoded salt>",
  "chunks": <integer: number of chunks>,
  "last_chunk_size": <integer: size of final chunk in bytes>,
  "argon2": {
    "time_cost": 2,
    "memory_kib": 64000,
    "parallelism": 4,
    "type": "argon2id"
  }
}
```

### Streaming Model
- **Memory efficient:** No intermediate files during backup creation (except temp dir)
- **RAII cleanup:** All streams/files automatically closed on exception or scope exit
- **Chunk-based encryption:** Enables parallel nonce generation and key derivation

### Progress Tracking Implementation

## 5. Known Issues & Bugs

### HIGH PRIORITY

#### BH-001: No Archive Integrity Verification
**Severity:** Critical  
**Location:** `libdvx3.vala`, `main.vala::decrypt_and_extract_stream()`  
**Description:** Archives lack cryptographic checksums for corruption detection.

**Current Implementation:**
```vala
// Header contains ONLY metadata (salt, chunks count, etc.)
var header = new Json.Object();
header.set_string_member("salt", Base64.encode(salt));
header.set_int_member("chunks", (int64)encoder.chunks);
// NO integrity field!
```

**Impact:**
- Data corruption undetected until restore attempt
- No way to verify archive health without risking data loss
- Catastrophic failure if chunk decryption fails

**Recommended Fix:** Add SHA-256 hash of plaintext computed during encryption.

---

#### BH-002: Progress Tracking Disabled
**Severity:** High  
**Location:** `libdvx3.vala::encrypt()` around line 232  
**Description:** GNU tar's SIGUSR1 dynamic progress tracking forcibly disabled.

**Current State:**
```vala
if (gnu_tar) {
  gnu_tar = false;  // ← FORCED DISABLE
}
// Falls back to static 50% compression estimate
```

**Impact:**
- Progress bar shows ~50% for all operations initially
- ETA calculations inaccurate for high-compression files
- User cannot distinguish "stuck" from "slow"

**Recommended Fix:** Restore SIGUSR1 monitoring with proper signal masking.

---

### MEDIUM PRIORITY

#### BH-003: Password Storage in Plaintext
**Severity:** Medium  
**Location:** `backup-manager.hpp::BackupJob` struct, config files  
**Description:** Encryption passwords stored unencrypted in user config.

**Current Implementation:**
```cpp
struct BackupJob {
    std::string name;
    std::string source_path;
    std::string backup_dir;
    std::string password;  // ← Plaintext!
    bool enabled;
};
```

**Mitigation:** Security.md documents: `chmod 600 ~/.config/backup-manager/backup-manager.conf`

**Recommended Fix:** Add optional user passphrase to encrypt password field.

---

#### BH-004: Limited Error Context in Subprocess Failures
**Severity:** Medium  
**Location:** `libdvx3.vala::encrypt()` fallback path  
**Description:** Error messages from failed subprocesses may be truncated or unclear.

**Current Implementation:**
```vala
if (!run_command_sync (tar_cmd, out cmd_out, out cmd_err, out cmd_status))
    throw new IOError.FAILED ("tar failed: " + (cmd_err ?? ""));
```

**Recommended Fix:** Add stderr buffering and line-by-line error extraction.

---

### LOW PRIORITY

#### BH-005: Inconsistent Temp Directory Cleanup
**Severity:** Low  
**Location:** Multiple temp directory creation points  
**Description:** Some operations use explicit `FileUtils.remove()` while others rely on OS cleanup.

**Recommended Fix:** Add try-finally blocks for all temp directory creation.

## 15. Glossary

| Term | Definition |
|------|------------|
| **Chunk** | Encrypted data unit: 1 MiB plaintext + nonce+MAC overhead |
| **Header reserve** | 512 bytes in archive header for dynamic metadata updates |
| **Master key** | Argon2id-derived 256-bit key used for all chunk encryption |
| **Subkey** | SHA-256(master_key || chunk_index) per-chunk subkey |
| **Payload** | Concatenation of nonce+ciphertext pairs (encrypted data blocks) |
| **TUI** | Terminal User Interface (text menu-driven backup manager) |
